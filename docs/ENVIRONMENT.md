## Воспроизведение

Из корня репозитория, Windows PowerShell 5.1:

```powershell
# Подготовить рабочие копии и записать журнал среды.
.\tools\Use-Environment.ps1

# Ограниченная проверка версии UZDoom (10 секунд), без запуска Смуты.
.\tools\Use-Environment.ps1 -Action Probe

# Отдельная проверка версии UZDoom.
.\tools\Use-Environment.ps1 -Action Version

# Интерактивный запуск эталона; завершить через интерфейс игры.
.\tools\Use-Environment.ps1 -Action Smuta

# Техническая комната UZD-01 после Build.ps1 -Task Standalone:
.\tools\Use-Environment.ps1 -Action UZDoom -Ipk3 .\build\uzd-01\smuta-uzd01.ipk3
```

Последняя команда запускает [технический IPK3 UZD-01](STANDALONE.md),
созданный 17 октября. Скрипт отклоняет отсутствующий файл.
Интерактивные команды запускают приложение без скрытия окна, перенаправления
stdout/stderr и тайм-аута и ждут завершения процесса;
Probe/Version запускают скрытые процессы с ограничением времени,
затем запрашивают закрытие и при необходимости принудительно останавливают
только созданный ими процесс. Тайм-аут не считается успешным завершением программы.

Скрипт копирует дистрибутивы в `build/run/smuta/` и `build/run/uzdoom/`.
Повторный запуск сохраняет существующие настройки и сохранения. Исполняемые
файлы и ресурсы копии сверяются с источником; при расхождении запуск блокируется.
Скрипт не очищает рабочие каталоги. При смене исходной сборки сначала следует
сохранить результаты предыдущих замеров и выделить новый `build/run/`.
Русский текст скрипта хранится как UTF-8 с BOM для Windows PowerShell 5.1.

## Пути записи

| Назначение | Рабочий путь |
| --- | --- |
| EXE, рабочий каталог, INI Смуты | `build/run/smuta/`, `smuta.ini` |
| Сохранения, снимки, результаты Смуты | `build/run/smuta/SAVE/`, `BMP/`, `ERROR/`, `TEST/` |
| EXE и рабочий каталог UZDoom | `build/run/uzdoom/` |
| Конфигурация UZDoom | `build/run/uzdoom/uzdoom.ini`, явно через `-config` |
| Сохранения UZDoom | `build/run/uzdoom/saves/`, явно через `-savedir` |
| Снимки UZDoom | `build/run/uzdoom/screenshots/`, явно через `-shotdir` |
| Журналы запусков | `build/run/logs/<UTC-время>/` |

Для UZDoom отключены autoload и autoexec; пакет задаётся полным путём через
`-iwad`, консольный журнал — через `+logfile`. Параметры конфигурации,
сохранений и автозагрузки сверены с [исходниками UZDoom 5.0.3](https://github.com/UZDoom/UZDoom/blob/5.0.3/src/d_main.cpp)
и [обработчиком конфигурации](https://github.com/UZDoom/UZDoom/blob/5.0.3/src/gameconfigfile.cpp).
`-shotdir` и описание его назначения также найдены в строках локального EXE.
Версия проверяется отдельной командой `-version` без игрового пакета.
Фактическая запись INI, сохранений и снимков UZDoom при игре ещё не проверена.

Каждый вызов пишет `sources-before.json`, `sources-after.json`, `environment.json`.
Для процессов сохраняются команда, рабочий каталог, PID, результат ожидания,
признак принудительной остановки; для проверки версии — stdout/stderr.
Для Смуты сохраняются ERROR.TXT до и после запуска, их хеши и признак изменения.
Существующие сообщения журнала нельзя считать новыми ошибками запуска.
`Completed` означает завершение сценария проверки, а не работоспособность игры;
результат процесса находится в отдельном JSON. `SourcesUnchanged` подтверждает
неизменность исходных файлов. Все рабочие файлы остаются под игнорируемым `build/`.

## Наблюдаемый результат и ограничения

Ниже сохранены результаты ENV-01 от 16 октября. Более поздняя проверка
игрового запуска технической комнаты находится в [приёмке UZD-01](STANDALONE.md).

Итоговая проверка: `build/run/logs/20261016T175544375Z/`.
Первичная проверка: `20261016T175305807Z`; повторная подготовка:
`20261016T175359956Z`. Первые вызовы `-version` без явной конфигурации
не завершились за тайм-аут. Итоговый скрипт задаёт пути записи и для проверки
версии; при таком вызове получен код 0. Причина различия отдельно не исследована.

- **Смута, первоначальная проба:** процесс создан со скрытым окном и остановлен
  после 5 секунд. Такой запуск не проверяет обычную интерактивную работу игры;
  незавершение игры за 5 секунд также не является признаком неисправности.
  Сообщения о видеорежиме и `Exception: DDERR_SURFACELOST` уже присутствуют
  в исходном `ERROR/ERROR.TXT` и были скопированы вместе со сборкой.
  В рабочем журнале добавились повторения сообщения о видеорежиме, но причина
  не установлена. Утверждение, что проба обнаружила новую `DDERR_SURFACELOST`
  и доказала недоступность игровых замеров, отозвано.
  Исходный INI имел `Video=5`; конфигурация не менялась.
- **Смута, сведения пользователя:** 16 октября 2026 года пользователь сообщил,
  что при обычном запуске игра работает. Это подтверждение пользователя,
  а не самостоятельная визуальная проверка агента. Игровые замеры ещё
  не проводились. Скрытый запуск Смуты исключён из `Probe`; для работы
  используется `-Action Smuta` с обычным окном и завершением через игру.
- **UZDoom:** процесс вывел версию и строку `M_LoadDefaults: Load system defaults.`,
  завершился самостоятельно до тайм-аута с кодом **0** при явных `-config`,
  `-savedir`, `-shotdir` и отключённой автозагрузке. Самостоятельного IPK3 пока нет,
  графика, звук и загрузка карты не проверялись. Проверка игрового запуска — UZD-01.
- **Статически:** DAT/EXE совпадают с хешами исследования; полные исходные
  каталоги Смуты и UZDoom неизменны после проверки. Подготовлены независимые
  рабочие копии. Оснований менять видеорежим или исправлять DirectDraw
  по результатам скрытой пробы нет.

Дополнительно проверены синтаксис скрипта средствами PowerShell, сохранение
хеша рабочего `smuta.ini` при повторной подготовке, отклонение отсутствующего
IPK3 и исключение рабочих файлов через `.gitignore`. Проверка `git diff --check`
не выявила ошибок пробелов.

Старт процесса и обнаружение версии не доказывают точность ремейка или
работоспособность всей игры. Это журнал доступности среды, а не игровой замер.

# GFX-01/GFX-02: декодирование графики и анимаций

Обновлено 17 октября 2026 года. **Декодирование GFX-01/GFX-02 завершено
в объёме подготовки ресурсов для генератора.** Правила хранения, палитры,
контекстной прозрачности, привязок, направлений и счётчика задержек установлены
по файлам и EXE. По решению пользователя точная визуальная и временная сверка
перенесена к работающим сценам UZDoom (UZD-02, PLAY-02, CHECK-02).
Это не приёмка игрового переноса: генератор и релиз пока не используют результат.
Ниже сохранён ход исследования; прежние отметки «не подтверждено» уточнены
в разделе «Итоговая проверка правил по EXE» в конце документа.

## Входы и команды

Эталон — современная сборка **Smutabor Patch**, не неизменённая игра 1997 года:

```text
SMUTA.DAT  6e13c4b65e4530291b11e3d4cd6280d874c489837e7e74c5f53b686ca69a74e8
SMUTA.EXE  1b7f8e5d010e225139f3a03f3721aff39d5e0b8c1c4ef42106c14002ea6405bb
uzdoom.exe e6df57d1027cee089d33388ab743817a236148992ac3881d9141ea2b547677d9
```

UZDoom: PE FileVersion **5.0.3**, не запускался в этой приёмке.
Python **3.14.6**, стандартная библиотека, без внешних пакетов.

```powershell
.\tools\Build.ps1 -Task Graphics
.\tools\Build.ps1 -Task Test
.\build\tools-venv\Scripts\python.exe -B .\tests\verify_graphics.py
```

`Graphics` принимает `-Source` (DAT) и `-Output` (новый/пустой каталог внутри
`build/` или `dist/`); по умолчанию `build/decoded/smuta-graphics/`.
Рядом с DAT обязательны все `Z0.SPR`…`Z10.SPR`. Неизвестный хеш DAT,
неполный набор внешних файлов, дубликат номера, неподдержанный формат,
неверные диапазоны и непустой выход вызывают ошибку. Проверка входов
завершается до записи. Выходы через ссылки/reparse points запрещены.

## Факты из файлов и EXE

- **97** записей с расширением `.SPR` (без учёта регистра) имеют размеры
  `uint16 LE` по смещениям 0/2 и ровно `width * height` байт после заголовка 18.
  `L09SN03.SPR`, индекс 103, действительно имеет размер **64×65**.
- Ещё **60** записей без расширения удовлетворяют той же структурной проверке.
  Индексы перечислены в `profiles/smuta/graphics.json`, привязанном к хешу DAT.
  Совпадение структуры не доказывает игровое назначение каждой записи.
  Включены `ЗАСТАВКА_СПР` 182, `ПАНЕЛЬ` 191, `UROVEN_SP` 357.
- EXE VA `00409C0C–00409C42`: после чтения ресурса поле `+14` заменяется
  указателем на начало данных `+18`; поля `+6` и `+8` устанавливаются в 1 и 0.
  Поле `+14` нельзя использовать как файловое смещение или точку привязки.
  Путь загрузки DAT `0041D904–0041D958` вызывает этот загрузчик.
  Профиль сохраняет VA, файловые смещения и исходные байты доказательств.
- **11** внешних `Z*.SPR` — BMP `BM`, DIB40, BI_RGB, 8 bpp, 320×200,
  `bfOffBits = 1078`. Реальный диапазон заканчивается на 65078,
  хотя `bfSize = 32539`. Исключение разрешено только явным параметром
  обработчика и при полном совпадении известных структурных условий.
  Другие несоответствия размера отклоняются; оригиналы не исправляются.
- В DAT индекс **183**, второй `ЗАСТАВКА_СПР`, — **BMP**, индекс 182 — SPR.
  Обе записи сохранены под индексными именами; правило DAT-02 выбирает 182.
- BMP-преобразование учитывает BGRX, выравнивание строки до четырёх байт,
  положительную (снизу вверх) и отрицательную высоту. EXE
  `0040A326–0040A43E` подтверждает переворот и BGR8 → RGB6 через `>> 2`.
  Это не доказывает обратный путь вывода RGB6 на экран.
- `GAMEP1` 189 и `ЗАСТАВКА_ПАЛ` 184: по 768 байт, компоненты 0…63.

## Преобразования и формат результата

`tools/smuta_build/graphics.py` отделён от DAT, IR и генерации UZDoom.
`decode_spr`, `decode_bmp`, `decode_palette` доступны отдельно.
SPR сохраняется без изменения индексов, масштабирования и обрезки.
Все 18 байт заголовка и неинтерпретированные поля записаны в метаданные.

**Гипотезы только для SPR-превью:** строки идут сверху вниз слева направо,
используется `GAMEP1` в порядке RGB, расширение компоненты — `value << 2`
(63 → 252). Даже для заставки выбор GAMEP1 — техническое превью,
а не доказанная привязка палитры. PNG непрозрачен; это не утверждает
непрозрачность ресурса в игре. `transparent_index` и `anchor` остаются `null`;
смещения Doom/PNG grAb не назначаются. Нулевой индекс не удаляется.
BMP-превью использует собственную палитру без RGB6-квантизации.

Манифест `smuta-graphics-research` v1 содержит SHA-256 DAT и профиля,
`release_ready: false`, блокировки, декодер, размеры, исходный заголовок,
диапазон пикселей, преобразования и статус проверки. Происхождение включает
игру, контейнер, индекс, имя и его байты, смещение, длину, SHA-256;
для внешнего файла — относительное имя, длину и хеш. Для SPR-превью
указаны кандидат палитры с происхождением и применённые преобразования.
Все выходные файлы имеют пути, размеры и хеши. Дат и абсолютных путей нет.

Имена файлов: `sm000182.source/.indices/.png` для DAT,
`smext00.source/.indices/.png` для внешнего файла. `.source` — полные исходные
байты, включая заполнение BMP и хвост. Имена DAT не используются как пути.
Палитры: `.rgb6` (исходные байты), `.rgb8` (кандидат для превью).
PNG индексный 8 bpp: разные индексы остаются различимыми при одинаковых цветах.
Манифест записывается последним; повторный вывод требует нового каталога.

### Начальное статическое исследование GFX-02

В сохранённом дизассемблировании того же EXE найдены следующие пути:

- `0041D95A–0041D9AF` загружает ресурс DAT через `00426C10`.
- `00426C10–00426C72`: таблица начинается с `+12`, число записей — signed word
  `+4`, размер записи — 10 байт. Указатель `+8` заголовка заменяется адресом
  таблицы. Поле `+6` каждой записи заменяется указателем на последовательный
  встроенный SPR; в SPR `+14` заменяется указателем `+18`, поле `+4` — на 8,
  следующий SPR начинается после `18 + uint32(+10)` байт.
- `004269F7–00426A94`: кадр ограничивается диапазоном `0…word(+2)-1`.
  При ненулевом signed word `a` по `+0` группа выбирается как
  `((angle + (a >> 1)) % 360) / a`, затем индекс равен
  `group * word(+2) + frame`. Это правило углов из кода, а не сопоставление
  сторон света или направлений Doom.
- `00426946–004269F6` увеличивает кадр; при достижении `word(+2)` возвращает
  null и устанавливает кадр в -1. Из 10-байтовой записи возвращаются три
  word по `+0/+2/+4` и SPR по `+6`.
- Потребитель `0041DCCC–0041DD4F` передаёт word записи `+0` в
  `00427D84–00427DA6`, где вычисляется целочисленное `value * 24 / 1000`.
  Это установленное преобразование для данного потребителя; оно ещё не
  доказывает измеренную длительность и поведение остальных потребителей.

Пробный структурный обход подтвердил последовательность таблица → встроенные
SPR до конца ресурса для FL с расширением и ряда ресурсов без расширения,
включая `TOPORA`, `AKM74_1`, `PIONR`, `KEYY` и `ТРУБА/2` (индекс 199).
Это разведочный результат: декодер FL, отслеживаемый каталог покрытия,
проверки повреждённых диапазонов и игровая сверка направлений/задержек ещё
не реализованы. GFX-02 не завершена; её критерий UZDoom также не проверялся.

## GFX-02: реализованный структурный декодер, 17 октября

`tools/smuta_build/animations.py` реализует `decode_fl`, выбор кадра
`frame_index` и отдельный исследовательский экспорт `decode_animations`.
Он не изменяет IR и не создаёт игровой пакет. Начальное исследование выше
продолжено: декодер, профиль и проверки теперь реализованы.

```powershell
.\tools\Build.ps1 -Task Animations -Output .\build\decoded\smuta-animations-gfx02
.\tools\Build.ps1 -Task Test
.\build\tools-venv\Scripts\python.exe -B .\tests\verify_animations.py
```

Выход должен быть новым/пустым внутри `build/` или `dist/`; ссылки запрещены.
Неизвестный DAT отклоняется по SHA-256 профиля. Все ресурсы декодируются до
первой записи. Исключений по имени или угаданной длине кадра нет.

### Формат по файлам и EXE

| Смещение FL | Тип | Установленное значение |
| --- | --- | --- |
| +0 | int16 LE | Шаг направления в градусах: 0, 9 или 45 в исследованном DAT; 0 означает одну группу |
| +2 | int16 LE | Кадров в одном направлении |
| +4 | int16 LE | Всего записей таблицы и встроенных SPR |
| +6 | int16 LE | Неинтерпретированное слово, сохраняется |
| +8 | uint32 LE | Сохранённое значение, заменяемое загрузчиком указателем на таблицу +12 |
| +12 | N × 10 байт | Три int16 (+0/+2/+4) и заменяемый указатель uint32 (+6) |
| +12 + N×10 | Последовательные SPR18 | Следующий начинается через 18 + uint32(SPR+10); длина обязана совпасть с width×height |

Поля указателей из файла не используются как смещения. Сохраняются исходные
12 байт заголовка, каждая запись таблицы, заголовки встроенных SPR и все
индексы пикселей. Проверяются положительные счётчики, соотношение
`total = frames_per_direction × directions`, делимость 360 на ненулевой шаг,
диапазоны таблицы/кадров, размеры SPR и отсутствие неразобранного хвоста.
Неподдержанная структура завершает экспорт ошибкой.

Таблица упорядочена сначала по направлению, затем по кадру. Для нормализованного
угла 0…359 воспроизведено правило EXE с целочисленным делением:
`direction = ((angle + step//2) % 360) // step`; при step=0 direction=0.
Индекс: `direction * frames_per_direction + frame`. Функция выбора ограничивает
кадр, как `004269F7`; отрицательные/ненормализованные углы отклоняет явно.
Соответствие угла ракурсу камеры/сторонам света ещё не доказано.

**98 анимаций, 1021 кадр:** 64 ресурса с `.FL` и 34 без расширения.
Шесть анимаций используют 8 направлений (45°): PIONR, BOJAR, STRELR, TOPOR,
STRU.FL, CHA.FL. Ещё пять имеют **40 направлений по 9°**, один кадр на ракурс:
KREST (255), CHEREP (256), KRUSH (263), CHERKL (271), APTEKA (272).
В частности, 40 кадров предмета не означают 40 последовательных кадров
временной анимации. Остальные 87 ресурсов имеют одну группу направления.
Полный каталог: [research/smuta-fl-catalog.csv](research/smuta-fl-catalog.csv).

Слова записей остаются `word0_raw`, `word2_raw`, `word4_raw`. Путь использования
word0 как параметра задержки и преобразование `value*24/1000` приведены выше;
задержки не переведены в секунды или тики Doom. События атаки, другие
потребители, округление планировщика и фактическое время ещё требуют сверки.

## Итоговая проверка правил по EXE

После автодемо выполнена статическая проверка оставшихся свойств. Источник —
тот же Smutabor Patch с хешами выше; новый запуск игры не выполнялся.
Диапазоны ниже — виртуальные адреса. Байты, файловые смещения и длины
сохранены в `render_evidence`/`timing_evidence` профиля
[`graphics.json`](../profiles/smuta/graphics.json) v2 и проверяются по EXE.

| Свойство | Установленное правило и источник |
| --- | --- |
| Хранение SPR | Построчно, сверху вниз; экранный blitter `00401F84–00402003`, текстурная колонка `00407180–00407250`. Переворачивать индексы SPR не требуется. |
| Палитра | Исходные тройки RGB6; преобразование канала `<<2`, то есть 63 → 252. `00404BB8–00404C02` записывает их в BGRX. Меню загружает GAMEP1 (`00424B3E–00424B8D`); все 42 текста уже ссылаются на GAMEP1. |
| Прозрачность | В маскированных ветвях пропускается исходный индекс 0, до освещения/смешивания. Экранный SPR: runtime-слово +4 равно 8 (`00401F22`). Мировой: бит 3 включает маску, бит 0 — смешивание (`00402280`, `00406F59`, `00407027`, `0040708F`). Непрозрачная ветвь рисует и ноль. Режим назначает потребитель, поэтому общей альфы для всех текстур нет. |
| Мировая привязка | Billboard строится от нижнего центра: X ± width/2, верх Y−height, низ Y (`0040E07C–0040E09F`, `0040E11B–0040E177`). Положение, масштаб и вертикальную поправку задаёт объект; это не поля указателей SPR. |
| Оружие | Слова +2/+4 записи FL — знаковые смещения экранных X/Y в пикселях исходного экрана в оружейном потребителе (`00421DBA–00421EBB`). Они добавляются к вычисленной экранной позиции; универсальной PNG-привязкой не являются. |
| Угол предмета | `0041E4B4–0041E5C0`: нормализованный угол объекта плюс результат функции угла от разности координат объект−камера; при отсутствующей/совпадающей камере 0. Выбор группы FL уже воспроизведён. Названия сторон света не назначаются. |
| Счётчик задержки | `N = floor(word0 * 24 / 1000)` для неотрицательного параметра (`00427D84–00427DA6`). Проверяется старое значение до декремента: callback через N+1 проходов (`00427E03–00427E46`), затем счётчик перезагружается. |
| Базовый шаг | `GetTickCount / 55` (`00409A78–00409A8A`, thunk `00432EB8` → IAT `0049B254`, импорт KERNEL32.GetTickCount). Главный цикл вызывает планировщик раз на логический проход, потребляет один накопленный шаг и ограничивает остаток двумя (`00425C57–00425CE1`). Это около 18,18 Гц. |

Номинальная задержка при регулярном главном цикле:
`(floor(word0 * 24 / 1000) + 1) * 55 мс`: параметры 1, 42, 100, 200 дают
55, 110, 165, 275 мс. Это вывод из кода, не измерение настенных часов:
под нагрузкой ограничение накопленных шагов меняет фактическое время.
Нельзя объявлять коэффициент 24 частотой игры или напрямую переводить word0
в миллисекунды/Doom-тиками. События выстрела задаются вызывающим игровым кодом,
а не неизвестным полем FL; их сверка относится к PLAY-02.

Декодеры и манифесты v2 включают правила рисования, а FL — также правила
времени, вычисленный `delay_counter_if_scheduled` и `weapon_screen_offset`.
Исходные слова остаются без изменений. PNG остаются непрозрачными превью:
альфу и привязки назначит генератор по роли ресурса.

Повторные проверки после уточнения: **65 тестов прошли**;
171 ресурс GFX-01; **98 FL, 1021 кадр, 7445 ссылок из 42 текстов** GFX-02.
Два экспорта каждого вида совпали побайтно, границы/пиксели/поля/байты EXE
проверены, хеши входов до и после совпали. Отчёты:

- `build/gfx-01 verification 75e7fc9e0c8544629ef03f4a98632bfb/report.json`;
- `build/gfx-02 verification 72824c22ea4641df8bd683f2b1e892fe/report.json`;
- [снимок метаданных проверки](research/gfx-rules-20261017-results.json).

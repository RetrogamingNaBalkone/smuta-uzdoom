# BUILD-01/QA-01: сборка и проверка запуска

Реализовано 17 октября 2026 года. Единая команда из корня проекта:

```powershell
.\tools\Build.ps1 -Task Verify
```

Требуются окружение Python из `Build.ps1 -Task Setup` и локальный дистрибутив
UZDoom в `uzdoom/`. Оригиналы Смуты, Doom IWAD, CD и предварительный
`Use-Environment.ps1 -Action Prepare` не нужны. Сейчас собирается техническая
комната UZD-01; это исследовательская сборка без механик Смуты и допуска к релизу.

Команда выполняет автономные тесты, создаёт два IPK3 и сравнивает их побайтно,
проверяет состав и хеш каждого файла по встроенному манифесту. Затем копирует
EXE, DLL и два обязательных PK3 движка в новый рабочий каталог и запускает
первый пакет с отдельными конфигурацией, сохранениями и журналами.
Исходный дистрибутив используется только для чтения; хеши файлов проверяются
до копирования и после запуска. В отчёте сохраняются также хеши инструментов
и игровых исходников. Абсолютные пути и результаты запуска находятся снаружи IPK3
и не нарушают его воспроизводимость.

По умолчанию каждый вызов создаёт `build/qa01 <id>/`. Можно задать новый
каталог и другой локальный дистрибутив:

```powershell
.\tools\Build.ps1 -Task Verify -Output '.\build\проверка с пробелами' -EngineSource '.\uzdoom'
```

Относительные параметры считаются от текущего каталога. Встроенные пути — от
корня проекта. Рабочая проверка разрешена только внутри `build/`; ссылки,
reparse points и существующий выходной каталог отклоняются. Повторный вызов
без параметров использует новый каталог, прежние результаты сохраняются.
Ошибка тестов останавливает команду до сборки; ошибка сборки — до запуска.
Ошибка конвейера возвращает ненулевой код, `report.json` сохраняет причину.

В каталоге результата находятся:

- `smuta.ipk3` и `repeat.ipk3` — два одинаковых игровых пакета;
- `runtime/` — отдельная рабочая копия движка;
- `observer.pk3` — технический наблюдатель, загружаемый только при проверке;
- `uzdoom.ini`, `engine.log`, `stderr.log`, `command.txt` — конфигурация и журналы;
- `report.json` — результат, параметры процесса, манифест входов и хеш пакета.

IPK3 содержит детерминированный `smuta-build-report.json`: хеши игровых
исходников и всех файлов пакета, `mode: synthetic-research`,
`release_ready: false`. Внешний отчёт имеет схему `smuta-qa01-v1`;
его время выполнения и пути не являются частью воспроизводимого пакета.

## Условия успешной проверки

Наблюдатель подтверждает карту `SMTEST`, класс игрока `SMProbePlayer`,
достижение 70 тиков и вызов отрисовки после 35 тиков. Журнал должен содержать
версию UZDoom, не иметь проверяемых ошибок скриптов, текстур или VM и показывать
ровно четыре ожидаемых архива в заданном порядке: ядро, `game_support`,
созданный IPK3 и наблюдатель. Автозагрузка, autoexec и опциональные графические
пакеты отключены. Новый каталог и журнал исключают зачёт прошлого запуска.

Тайм-аут по умолчанию — 25 секунд. По завершении наблюдения останавливается
только созданный процесс; его код после принудительной остановки не трактуется
как штатный выход. Раннее завершение и тайм-аут являются ошибкой.
Это техническая проверка загрузки и кадра, без оценки точности изображения,
механик, меню и штатного выхода. Такая сверка остаётся в последующих пунктах плана.

Реализация: `tools/smuta_build/pipeline.py`; CLI:
`python -B -m smuta_build verify [--output <каталог>] [--engine-source <каталог>]`.
Для диагностики CLI принимает `--timeout` в пределах (0, 120] секунд.
Следующие игровые компоненты следует подключать к этой команде,
расширяя генератор и критерии запуска по мере реализации.

## Приёмка 17 октября 2026

На Windows PowerShell 5.1, Python 3.14.6 и UZDoom 5.0.3 прошли 86 автономных
тестов и запуск полной команды. Проверены отказы при ошибке сборки,
отсутствии движка, повторном выходном каталоге, недопустимом пути, неверном
игроке, отсутствии кадра, постороннем архиве и ошибке VM.
Отдельный реальный запуск с `--timeout 0.01` завершился ненулевым кодом:
в отчёте `passed: false`, `timed_out: true`, исходники движка не изменились.
